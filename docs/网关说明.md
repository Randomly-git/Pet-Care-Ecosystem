# 网关接入说明文档

## 📌 更新概览

原多端口直连方式已升级为**单网关统一入口**模式，前端只需连接网关端口，由网关自动路由到对应微服务。

## 🔗 连接信息

| 项目 | 原配置 | 新配置 | 说明 |
|------|--------|--------|------|
| **统一入口** | 多个不同端口 | `http://服务器IP:9000` | **前端唯一需要连接的地址** |
| 后端服务 | 直接连接各微服务 | 通过网关路由 | 前端无需感知具体服务端口 |

## ⚙️ 前端配置示例

### 原配置（需要修改）
```javascript
// 分别配置不同服务的baseURL
const authApi = axios.create({ baseURL: 'http://localhost:8082' });
const mediaApi = axios.create({ baseURL: 'http://localhost:8081' });
const communityApi = axios.create({ baseURL: 'http://localhost:8084' });
// ... 其他服务
```

### 新配置（推荐）
```javascript
// 只需配置一个网关地址
const gatewayBaseURL = 'http://localhost:9000';

// 统一使用网关地址
const api = axios.create({ baseURL: gatewayBaseURL });

// 所有请求都通过网关（url仅为示例，并非真实的）
api.get('/api/pets/list');                // → 路由到宠物管理服务
api.post('/api/media/upload');             // → 路由到媒体服务
api.get('/api/v1/moments');                // → 路由到社区服务
api.post('/api/chat/send');                // → 路由到LLM服务
api.get('/api/stats/activity/daily');      // → 路由到统计服务
```

### 或保持原有API结构
```javascript
// 如果前端不想改动太多，只需修改baseURL
const apiConfig = {
  baseURL: 'http://localhost:9000',  // 改为网关地址
  timeout: 10000
};

// 原有的API接口定义可以保持不变（url仅为示例，并非真实的）
const apis = {
  // 宠物相关
  getPets: '/api/pets/list',
  createPet: '/api/pets/create',
  
  // 媒体相关

  // 社区相关
  getMoments: '/api/v1/moments',

  // LLM相关

  // 统计相关

```

## ✅ 优势与特性

### 1. **统一入口**
- 前端只需维护一个连接地址
- 简化网络配置和错误处理

### 2. **负载均衡**
- 自动实现服务实例的负载均衡
- 支持服务多实例部署

### 3. **服务发现**
- 后端服务动态注册/发现
- 服务重启或扩容不影响前端

### 4. **跨域处理**
- 已在网关统一处理CORS
- 前端无需再配置跨域代理

### 5. **高可用**
- 网关支持集群部署
- 后端服务故障自动转移

## 🚨 注意事项

1. **路径一致性**
   - API路径前缀保持不变
   - 仅域名/端口部分改变

2. **WebSocket支持**
   - 如使用WebSocket，需确认网关配置支持
   - 连接地址相应改为 `ws://服务器IP:9000/路径`

3. **文件上传**
   - 大文件上传可能需要调整网关超时时间
   - 测试文件上传功能是否正常

4. **本地开发**
   - 本地开发时网关地址为 `http://localhost:9000`
   - 确保本地Nacos和所有微服务正常运行

## 📞 问题排查

如遇到连接问题，请按以下步骤检查：

1. 确认网关服务是否启动（端口9000）
2. 确认Nacos服务是否运行（端口8848）
3. 检查后端服务是否在Nacos注册成功
4. 查看网关日志获取详细错误信息
5. 验证API路径是否符合路由规则
