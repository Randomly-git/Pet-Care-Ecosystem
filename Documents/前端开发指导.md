# 🐾 前端开发指导 (Front-end Development Guide)

## 1. 社区消息系统 (Notification System)

**用例描述**: 用户实时接收点赞、评论通知，并在点击后消除未读状态。

### 开发步骤:
1.  **WebSocket 连接**: 
    - 应用启动时，连接到网关 WebSocket 端点 `ws://localhost:9000/ws`。
    - 订阅个人路径: `/queue/user/{userId}`。
2.  **实时提示**: 
    - 收到消息后，使用 `ElNotification` 或 `Toast` 弹出提醒。
    - 更新全局 Store 中的 `unreadCount`。
3.  **消息中心列表**:
    - 调用 `GET /api/v1/notifications` 获取历史通知。
4.  **已读反馈**:
    - 当用户点击单条消息或进入消息页面时，调用 `PUT /api/v1/notifications/{id}/read`。

## 2. 冷热分离逻辑适配 (Cold Storage Strategy)

**用例描述**: 提高系统性能，历史记录只读化，且只有在用户明确请求时加载海量历史数据。

### A. 活动记录修改限制 (30天原则)
-   **逻辑**: 在 `ActivitiesView.vue` 渲染记录卡片时，计算 `activityDate` 与当前时间的差值。
-   **代码逻辑**:
    ```javascript
    const isReadOnly = (activityDate) => {
      const diffDays = (new Date() - new Date(activityDate)) / (1000 * 60 * 60 * 24);
      return diffDays > 30;
    };
    ```
-   **UI表现**: 若 `isReadOnly` 为 true，隐藏“编辑”和“删除”按钮，并显示“已归档”图标。

### B. 社区动态“查看不活跃帖子”
-   **场景**: 社区首页默认仅加载 MySQL 中的“热数据”（最近7天活跃）。
-   **操作流程**:
    1.  列表底部添加按钮 `[ 查看更多历史动态 (包含不活跃) ]`。
    2.  点击后，在 API 请求中加入参数 `includeCold=true`。
    3.  **触发恢复**: 后端检测到该请求后，会触发从 HBase 到热库的异步恢复逻辑，前端应显示加载动画并提示：“正在从冷库调取数据，请稍候...”。

## 3. 定时活动记录与提醒 (Scheduled Reminders)

**用例描述**: 为宠物设置规律性的喂食、喂药提醒。

### 功能设计:
1.  **单次提醒 (One-time)**:
    -   **API**: `POST /api/reserved-activities`。
    -   **参数**: `{ petId, activityId, reminderDate }`。
    -   **前端**: 使用 `el-date-picker` 的 `datetime` 类型，设置 `disabledDate` 禁选过去的时间。

2.  **有规律提醒 (Recurring/Schedule)**:
    -   **UI设计**: 在“记录活动”弹窗中增加“设为定时任务”开关。
    -   **API**: `POST /api/fixed-activities`。
    -   **核心字段**: `gapTime` (间隔天数)。例如设置每 7 天洗澡一次。

3.  **提醒反馈流程 (Reminder Feedback)**:
    -   **首页主动弹窗**: 进入页面后调用 `GET /api/reminders/pet/{petId}/overdue` 检查是否有未完成的任务。
    -   **操作选项**:
        -   **推迟**: 调用 `PUT /api/reminders/{id}/postpone`，UI 上该提醒消失。
        -   **完成**: 调用 `PUT /api/reminders/{id}/confirm`。
        -   **重要说明**: 确认完成后，后端会自动在“活动记录”中插入数据，前端应刷新 `ActivitiesView` 的时间线列表。

## 4. 冷媒体文件恢复用例 (Cold Media Recovery)

**用例描述**: 当用户浏览到较早之前的动态、活动或状态记录时，媒体文件（图片/视频/文档）可能已进入冷库。前端需引导用户手动触发恢复流程。

### 4.1 状态判断与 UI 交互
1.  **识别状态**: 检查后端返回的媒体对象字段 `status === 'Cold'`。
2.  **视觉反馈**:
    -   **图片/视频**: 在 `HomeView.vue` 或 `MomentCard.vue` 中，对冷数据应用滤镜：`filter: blur(8px) grayscale(100%);`。
    -   **蒙层提示**: 在模糊的组件上方覆盖一个半透明遮罩，显示“文件已归档”字样。
3.  **触发恢复**: 用户点击“解冻”或“点击查看”按钮。

### 4.2 涉及的 API

**接口地址**: `POST /api/media/{mediaId}/restore`

**响应逻辑**:
- **200 OK**: 触发异步恢复成功，前端显示“正在从云端调取，请在 1-3 分钟后刷新”。
- **409 Conflict**: 文件已在恢复中，请勿重复点击。

### 4.3 前端代码示例 (Vue 3)
```html
<div class="media-container">
  <img :src="media.fileUrl" :class="{ 'is-cold': media.status === 'Cold' }" />
  
  <!-- 仅当 status 为 Cold 时显示解冻按钮 -->
  <div v-if="media.status === 'Cold'" class="overlay">
    <el-button type="primary" @click="handleRestore(media.mediaId)">
      点击解冻资源
    </el-button>
  </div>
</div>
```

## 5. 常见问题 (FAQ)
-   **Q: 如何处理分页加载？**
    -   A: 始终使用后端返回的 `totalPages` 判断。对于活动记录，HBase 分页依赖于 RowKey 的 `startRow` 和 `stopRow`，前端只需传递 `page` 索引即可。
-   **Q: 为什么获取到的媒体文件 URL 无法访问？**
    -   A: 如果 `status` 为 `Hot` 但仍 404，请检查网关配置。如果为 `Cold`，必须调用 `restore` 接口。
