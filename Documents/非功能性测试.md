## 二、性能测试

### 2.1 数据库查询性能分析

**需要记录的统计数据**：

| 指标               | 获取方式               | 目标值   |
| ------------------ | ---------------------- | -------- |
| 单表查询耗时       | JPA SQL 日志           | < 50ms   |
| 联表查询耗时       | JPA SQL 日志           | < 200ms  |
| N+1 查询检测       | 日志中重复的 SELECT 数 | 0 次 N+1 |
| 数据库连接池使用率 | `HikariCP` metrics     | < 80%    |

### 2.2 API 响应时间基准测试（JMeter / k6）

选择 6 个核心端点，每端点发 100 次请求：

**需要记录的统计数据**：

| 指标                   | 目标值     |
| ---------------------- | ---------- |
| **平均响应时间 (avg)** | < 200ms    |
| **P95 响应时间**       | < 500ms    |
| **P99 响应时间**       | < 1s       |
| **最大响应时间 (max)** | < 2s       |
| **吞吐量 (req/s)**     | 记录实际值 |
| **失败率**             | < 0.1%     |

### 2.3 批量操作性能

| 指标                   | 测试数据                                                     | 目标值 |
| ---------------------- | ------------------------------------------------------------ | ------ |
| 单条上传 1MB 文件耗时  | [POST /api/media/upload](vscode-file://vscode-app/e:/Microsoft VS Code/0958016b2a/resources/app/out/vs/code/electron-browser/workbench/workbench.html) | < 1s   |

### 2.4 并发压力测试

**需要记录的统计数据**：

| 指标               | 说明                                |
| ------------------ | ----------------------------------- |
| **系统瓶颈点**     | 哪个微服务/端点最先出现响应时间飙升 |
| **最大并发数**     | 系统能稳定处理的最大并发请求数      |
