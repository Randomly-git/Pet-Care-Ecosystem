# 认证漏洞修复报告

## 漏洞描述

**CVE 等级类比**：🔴 HIGH — 未授权访问 (Broken Access Control)

### 根因

| 组件 | 状态 |
|------|------|
| `JwtTokenUtil.java` | ✅ 已存在 — 生成/验证 Token 的逻辑完整 |
| `jjwt-api:0.11.5` | ✅ 已存在 — JWT 依赖已引入 |
| `AuthController` (`/api/auth/login`) | ✅ 已存在 — 登录接口正常 |
| **`WebMvcConfigurer.addInterceptors()`** | ❌ **缺失** — 从未注册 JWT 拦截器 |
| **`HandlerInterceptor`** | ❌ **缺失** — 无人读取 Authorization Header |
| **`@PreAuthorize`** | ❌ 未使用 — Controller 方法无权限注解 |

### 攻击链

```
curl http://localhost:9000/api/pets/1  （不带 Authorization Header）
  → Gateway 路由到 petcare-backend
  → PetController.getPetById() 直接执行业务逻辑
  → 返回完整宠物数据（无任何拦截）
```

### 修复措施

1. **新建** `JwtAuthInterceptor.java` — 读取 `Authorization: Bearer <token>`，验证并提取 `userId`
2. **新建** `WebMvcConfig.java` — 注册拦截器到 `/api/**`，排除 `/api/auth/**`
3. **删除** `CorsConfig.java` — 功能合并到 `WebMvcConfig`，避免 Bean 冲突

### 修复后状态

| 路径 | 认证要求 |
|------|----------|
| `GET /api/auth/**` | ⬜ 放行（登录/注册必须无认证） |
| `GET /api/pets/**` | 🔒 需要 `Authorization: Bearer <token>` |
| `POST /api/activities/**` | 🔒 需要 Token |
| `GET /api/status/**` | 🔒 需要 Token |
| `GET /api/reminders/**` | 🔒 需要 Token |

### 验证命令（需要重启 petcare-backend 后执行）

```bash
# 应返回 401
curl -s http://localhost:9000/api/pets/1

# 先登录获取 Token
TOKEN=$(curl -s -X POST http://localhost:9000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | ...)

# 带 Token 应返回 200
curl -s http://localhost:9000/api/pets/1 \
  -H "Authorization: Bearer $TOKEN"
```
