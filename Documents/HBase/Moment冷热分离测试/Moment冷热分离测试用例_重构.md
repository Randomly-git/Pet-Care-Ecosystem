# Moment 冷热分离测试用例清单 (重构分组版)

## 1. 测试架构建模

在复杂的分布式系统测试中，风险维度与执行套组并非简单的线性对应。下图展示了 5 大质量风险是如何通过 5 个逻辑套组实现全方位交叉验证的：

```
@startuml
' 强制绘图方向为从左到右
left to right direction

' 样式美化
skinparam rectangle {
    BackgroundColor<<Risk>> #f9f9f9
    BorderColor<<Risk>> #FF33CC
    RoundCorner 20
}

skinparam rectangle {
    BackgroundColor<<Suite>> #e8f0fe
    BorderColor<<Suite>> #3366FF
}

title 质量风险与测试套组映射

' 定义左侧风险维度
package "质量风险类别" as Risks {
    rectangle "1.1 数据一致性风险" as R1 <<Risk>>
    rectangle "1.2 数据完整性风险" as R2 <<Risk>>
    rectangle "1.3 并发控制风险" as R3 <<Risk>>
    rectangle "1.4 系统稳定性风险" as R4 <<Risk>>
    rectangle "1.5 功能可用性风险" as R5 <<Risk>>
}

' 定义右侧测试套组
package "测试套组 Test Suites" as Suites {
    rectangle "TS-1 一致性与原子性" as TS1 <<Suite>>
    rectangle "TS-2 数据完整性" as TS2 <<Suite>>
    rectangle "TS-3 并发保护" as TS3 <<Suite>>
    rectangle "TS-4 稳定性与拦截" as TS4 <<Suite>>
    rectangle "TS-5 业务规则与边界" as TS5 <<Suite>>
}

' 映射关系
R1 --> TS1
R1 --> TS5

R2 --> TS2
R2 --> TS1

R3 --> TS3
R3 --> TS2

R4 --> TS4
R4 --> TS1

R5 --> TS5
R5 --> TS2

@enduml
```

## 2. 优化后的测试用例表

| Test Suite | 用例 ID | 关联 TCI | 测试场景 | 前置条件 | 测试步骤 | 预期结果 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **TS-1 Data Consistency (一致性与原子性)** | **TC-1-01** | TCI-STT-01, 05, TCI-DT-04 | 标准全生命周期成功路径与自愈 | APPROVED, 访问>168h | 1. 触发正常迁移。<br>2. 模拟 MIGRATING 遗留数据重试。 | 经历 NONE->MIGRATING->COLD；自愈逻辑通过 HBase exists() 幂等跳过并清理 MySQL。 |
| | **TC-1-02** | TCI-DT-03 | MySQL 删除阶段超时回滚 | 数据库行级独占锁 | 在写入 HBase 成功后，对 MySQL 目标行加锁模拟超时。 | 状态保持 MIGRATING，Spring 事务安全回滚，MySQL 记录不被误删。 |
| | **TC-1-03** | TCI-DT-01, TCI-STT-03 | 存储基础设施故障回滚 | HBase 连接断开 | 在写入 HBase 瞬间注入 IOException。 | 全局事务回滚，MySQL 迁移状态回滚为 NONE，确保数据不丢失。 |
| | **TC-1-04** | TCI-DT-02 | 虚假写入成功校验拦截 | Put=OK, Exists=False | Mock HBase 写入返回成功，但 exists 验证返回失败。 | 识别校验异常，触发事务强制回滚，MySQL 状态恢复为 NONE。 |
| **TS-2 Data Integrity (数据完整性)** | **TC-2-01** | TCI-STT-06, 07, 12 | 冷数据综合恢复全链路 | 状态: COLD, 原审: REJECTED | 1. 分页补齐触发隐式恢复。<br>2. 用户点击按钮触发显式恢复。 | 1. 列表返回混合数据。<br>2. 恢复后 MySQL 状态为 NONE，且审核状态保持 REJECTED 不变。 |
| **TS-3 Concurrency Control (并发保护)** | **TC-3-01** | TCI-STT-04, 11 | 迁移锁保护与物理删除 | 状态: MIGRATING | 1. 迁移中执行点赞/评论/修改。<br>2. 迁移中管理员执行物理删除。 | 1. 系统抛出异常屏蔽写操作。<br>2. 物理删除同步清理热/冷两端记录。 |
| **TS-4 System Stability (系统稳定性)** | **TC-4-01** | TCI-STT-Neg-01 | 重复审核操作拦截 | 状态: APPROVED | 管理员对已审核动态再次尝试审核通过。 | 接口返回更新失败或 0 行变更，防止审计轨迹被覆盖。 |
| | **TC-4-02** | TCI-STT-Neg-02 | 重复恢复事件拦截 | 状态: NONE (ACTIVE) | 模拟 MQ 重复推送 RESTORE 事件。 | 识别到热库已存在记录，幂等丢弃事件，不发生主键冲突。 |
| **TS-5 Functionality & BVA (业务规则与边界)** | **TC-5-01** | TCI-STT-02, 13, TCI-BVA-01-D | 迁移准入决策过滤器 | 评论: 2001 / 状态: PENDING | 分别使用该数据触发迁移任务。 | 任务识别不符准入条件（ Rule 3），静默跳过或瞬时解锁，不进入锁定流程。 |
| | **TC-5-02** | TCI-STT-09, 14 | 审核流转与可见性 | 状态: PENDING | 1. 非作者用户查询。<br>2. 管理员执行审核流转。 | 1. PENDING 状态全站不可见。<br>2. 状态正确流向 APPROVED 或 REJECTED。 |
| | **TC-5-03** | TCI-STT-10, 08 | 互动行为与热度重置 | 动作: 修改 / 详情查看 | 1. 修改已审核内容。<br>2. 用户访问动态详情。 | 1. 审核态重置为 PENDING。<br>2. last_access 时间更新，重新开始 7 天冷却。 |
| | **TC-5-04** | TCI-BVA-01-A, B, C | 评论数有效边界测试 | 评论: {0, 1999, 2000} | 使用不同评论数的动态触发迁移。 | 均符合准入条件，成功归档至 HBase。 |
| | **TC-5-05A** | TCI-BVA-02-B, C | REJECTED 状态有效边界 | 时间: {72h, 73h} | 针对被拒绝动态触发任务。 | 到达 3 天阈值，正常执行迁移。 |
| | **TC-5-05B** | TCI-BVA-02-A | REJECTED 状态无效边界 | 时间: {71h} | 针对被拒绝动态触发任务。 | 未达 3 天阈值，任务静默跳过。 |
| | **TC-5-06A** | TCI-BVA-03-B, C | APPROVED 状态有效边界 | 时间: {168h, 169h} | 针对已通过动态触发任务。 | 到达 7 天阈值，正常执行迁移。 |
| | **TC-5-06B** | TCI-BVA-03-A | APPROVED 状态无效边界 | 时间: {167h} | 针对已通过动态触发任务。 | 未达 7 天阈值，任务静默跳过。 |
