# 媒体文件微服务（media-backend）黑盒测试表

> **测试对象**：`media-backend` 模块  
> **核心 API**：`POST /api/media/upload`、`GET /api/media/{mediaId}`、`GET /api/media/related/{relatedType}/{relatedId}`、`DELETE /api/media/{mediaId}`、`DELETE /api/media/related/{relatedType}/{relatedId}`、`PATCH /api/media/batch/related`  
> **分析日期**：2026-05-19

---

## 表1：等价类表

| 输入条件 | 有效等价类 | 无效等价类 |
|----------|-----------|-----------|
| **file（上传的文件）** | ① 非空图片文件（如 `test.jpg`，>0 字节）  ② 非空视频文件（如 `test.mp4`，>0 字节）  ③ 含有效扩展名的文档文件（如 `.pdf`） | ④ 空文件（大小=0 字节）  ⑤ `null`（未传 `file` 参数） |
| **file 的 Content-Type** | ⑥ 标准 MIME 类型（`image/jpeg`、`video/mp4` 等）  ⑦ Content-Type 为 `null` 或空 → 系统从文件名推断 | ⑧ 无 |
| **mediaId（单个媒体文件ID）** | ⑨ 存在于数据库的正整数（如 `1`）  ⑩ 已在 COS 上对应文件存在的 ID | ⑪ 不存在的 ID（如 `99999`）  ⑫ 非正整数值（`0`、`-1`）  ⑬ 非数字类型（`"abc"`） |
| **userId（上传用户ID）** | ⑭ 有效的正整数用户ID（如 `1`、`100`） | ⑮ `null`（不传参数）  ⑯ 非正整数值（`0`、`-5`）  ⑰ 非数字类型（`"abc"`） |
| **relatedType（关联业务类型）** | ⑱ 合法枚举值：`"MOMENT"`  ⑲ 合法枚举值：`"ACTIVITY"`  ⑳ 合法枚举值：`"STATUS"`  ㉑ 合法枚举值：`"USER_AVATAR"` | ㉒ `null`/空字符串  ㉓ 不存在的类型（如 `"POST"`、`"COMMENT"`）  ㉔ 纯数字字符串（`"123"`） |
| **relatedId（关联业务实体ID）** | ㉕ 有效的正整数值（如 `1`、`50`） | ㉖ `null`（不传参数）  ㉗ 非正整数值（`0`、`-1`） |
| **mediaIds（批量关联的ID列表）** | ㉘ 含 1 个有效 ID 的列表（如 `[1]`）  ㉙ 含多个有效 ID 的列表（如 `[1, 2, 3]`） | ㉚ 空列表 `[]`  ㉛ `null`  ㉜ 列表中包含不存在的 ID（如 `[1, 99999]`） |
| **批量关联请求体完整性** | ㉝ `mediaIds`、`relatedType`、`newRelatedId` 均有效提供 | ㉞ 缺少 `mediaIds` 字段  ㉟ 缺少 `relatedType` 字段  ㊱ 缺少 `newRelatedId` 字段 |
| **文件大小** | ㊲ 小文件（<1MB）  ㊳ 中等文件（1MB~10MB）  ㊴ 大文件（10MB~100MB） | ㊵ 超大文件（超出 COS / 服务限制，如 >500MB） |

> **⚠️ 代码风险提示**（基于等价类分析发现）：
> - **TI-04 / TI-08**：`userId` 和 `relatedId` 未做 `>0` 校验，允许 `0` 和负值入库，存在脏数据风险
> - **TI-14**：批量关联时，不存在的 `mediaId` 不会被明确报错，可能静默失败
> - **TI-17**：文件大小无服务端显式限制（仅依赖 Spring 默认值和 COS 限制）
